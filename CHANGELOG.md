## 2026-11-05 — Убрано предупреждение HF Hub о неаутентифицированных запросах

### Что сделано

- Настройка окружения Hugging Face вынесена в новый модуль `src/hf_env.py` и подключается в `retriever.py`/`embed_and_index.py` до импорта `sentence_transformers` (HF-библиотеки читают env при своём импорте).
- Если веса обеих моделей уже лежат в `hf_cache/`, автоматически включается `HF_HUB_OFFLINE=1`: HF Hub больше не делает сетевых запросов при каждой загрузке модели, поэтому предупреждение `Warning: You are sending unauthenticated requests to the HF Hub. Please set a HF_TOKEN...` больше не печатается в терминал (и не ломает область ввода CLI/TUI). Заодно прогрев моделей стал быстрее — нет round-trip'а к API Hub.
- Явные настройки пользователя имеют приоритет: `HF_TOKEN` (или `HUGGING_FACE_HUB_TOKEN`) из `.env`/окружения оставляет онлайн-режим с аутентификацией; `HF_HUB_OFFLINE=0/1` и `TRANSFORMERS_OFFLINE` принудительно задают режим. Если кэша моделей нет (первый запуск на новой машине), офлайн не включается — модели скачаются как раньше.
- В `.env.example` и `.env` добавлен закомментированный `HF_TOKEN` с пояснением.

### Ошибки и исправления

- **Предупреждение о неаутентифицированных запросах периодически выскакивало в области ввода** — `sentence_transformers` при загрузке модели обращался к HF Hub за метаданными без токена, и библиотека печатала warning в stderr поверх перерисованного экрана. Исправлено авто-офлайном при наличии весов в кэше (запросы к Hub в этом случае не нужны вовсе).

### Проверки

- Воспроизведён исходный warning при загрузке модели; после исправления обе модели (эмбеддинги и reranker) грузятся без единой строки в stderr.
- Логика авто-офлайна: кэш есть → `HF_HUB_OFFLINE=1`; кэш пуст → остаётся онлайн; `HF_TOKEN` задан → остаётся онлайн; явный `HF_HUB_OFFLINE=0` не перезаписывается.
- `py_compile` + импорт всех затронутых модулей (`retriever`, `embed_and_index`, `cli`, `chat`, `tui`) без ошибок.

## 2026-11-05 — Автодополнение команд по Tab

### Что сделано

- В TUI (`src/tui.py`) команды чата дополняются по клавише Tab прямо в строке ввода: первый Tab дополняет набранный префикс (например, `/s` → `/sources`), повторные нажатия перебирают варианты по кругу, `Shift+Tab` перебирает назад. Если совпадений несколько и у них есть общий префикс длиннее набранного, первый Tab дополняет до него, следующие — перебирают.
- Дополнение работает только в командном контексте (строка начинается с `/`); вне его Tab сохраняет обычное поведение (перевод фокуса). При отсутствии совпадений или успешном дополнении статусная строка показывает подсказку — в том числе описание дополненной команды.
- Список команд вынесен в константы `COMMANDS`/`COMMAND_DESCRIPTIONS` в `tui.py` — единственное место для правки при добавлении новых команд.
- Fallback-CLI (`src/cli.py`) тоже получил автодополнение по Tab через readline (POSIX): `/exit`, `/quit`, `/sources`. На macOS (libedit) Tab привязывается через `bind ^I rl_complete`, на Linux (GNU readline) — через `tab: complete`; разделители слов ограничены пробельными символами, иначе `/` отрезалась бы от набираемой команды.
- Справка TUI (F1) и `README.md` дополнены строками про Tab/Shift+Tab; в подсказке строки ввода упомянуто автодополнение.

### Проверки

- Headless-тест Textual на реальном `MechanicusApp`: однозначное дополнение `/s` → `/sources`; перебор всех шести команд вперёд с зацикливанием и назад; сброс цикла после ручного редактирования; отсутствие совпадений; Tab вне командного контекста не меняет текст и не вставляет символ табуляции.
- Отдельно проверена ветка общего префикса на искусственном списке команд с общим началом.
- PTY-тест fallback-CLI на macOS: ввод `/s` + Tab в реальном терминале возвращает `/sources` (проверен и баг libedit — без переопределения разделителей completer получал `s` вместо `/s`).

## 2026-11-05 — Починены переключатели в настройках и остановка фоновой музыки

### Что сделано

- `start_background_music()` стала идемпотентной: повторный вызов при уже играющей музыке не заводит второй фоновый поток.
- Цикл воспроизведения хранит процесс в локальной переменной и проверяет stop-событие под тем же локом, что и `stop_background_music()` — устранены гонки «spawn/stop», при которых новый процесс мог пережить остановку.
- Обработчик `Switch.Changed` в `SettingsModal` игнорирует события, не меняющие состояние приложения: при открытии настроек `on_mount()` выставляет текущие значения переключателей, и Textual рассылает `Changed` — раньше это повторно запускало музыку.

### Ошибки и исправления

- **Переключатель музыки не выключал музыку** — при открытии настроек с включённой музыкой `on_mount()` сбрасывал значение переключателя, что рассылало `Switch.Changed` и повторно вызывало `start_background_music()`. Заводился второй поток со своим stop-событием; `stop_background_music()` останавливал только последний поток, а старый продолжал крутить трек (и перезапускал его после завершения). Исправлено: повторный старт игнорируется, если музыка уже играет; sync-события от `on_mount` не вызывают побочных эффектов; процесс, спавненный в момент остановки, гасится самим циклом воспроизведения.

### Проверки

- Сценарии фоновой музыки (подставной плеер вместо afplay): тройной `start` → один процесс → `stop` гасит всё; три цикла on/off; гонка `start`/`stop` ×20; `stop` без запуска — все прошли.
- Headless-тест Textual на реальном `MechanicusApp`: клики по всем переключателям настроек меняют состояние приложения, включение/выключение музыки вызывает ровно один `start`/`stop`, открытие настроек не перезапускает музыку.

## 2026-11-05 — Живой формат ответов: заголовок + рассказ

### Что сделано

- Убран шаблонный формат ответов (короткое предложение + 2–4 пункта с дефисами): бот теперь отвечает как живой архивариус — разговорная проза от первого лица, лёгкий колорит хранителя архива, без заученных ритуальных рамок.
- Новый формат: первая строка — жирный заголовок по теме (3–7 слов), дальше рассказ абзацами. Объём свободный: от 2–3 предложений до нескольких абзацев в зависимости от найденных данных; списки разрешены только когда это естественно.
- В TUI заголовок рендерится латунью жирным, тело — тёмно-зелёным, `**жирные акценты**` модели подхватываются; эффект печатной машинки сохранён (печатается готовый стилизованный текст, стили проявляются по мере печати).
- При нехватке данных — короткая честная реплика без заголовка с предложением переформулировать вопрос.
- CLI-fallback снимает звёздочки при печати; `strip_markdown` больше не удаляет `**жирный**` (его форматирует TUI).

### Проверки

- Юнит-проверки `_format_reply`: стили заголовка/тела/акцентов, fallback без заголовка, заголовок без тела.
- Headless-сценарий Textual: ответ отрисован без звёздочек, заголовок и акценты на месте; SVG-скриншот подтверждает вид (латунный жирный заголовок, пустая строка, зелёная проза).

## 2026-11-01 — Новый интерфейс в стиле arct (Textual)

### Что сделано

- Заменён построчный CLI-интерфейс на полноэкранный TUI в стиле arc-academy-terminal (arct) на фреймворке Textual 8.2.8.
- Новый файл `src/tui.py` (~1200 строк): прокручиваемая история чата (колесо мыши, PgUp/PgDn, Ctrl+U/Ctrl+D), строка ввода внизу с историей вопросов (↑/↓), нижняя панель горячих клавиш (как в arct), боковая панель источников последнего ответа (Ctrl+F), командная палитра (Ctrl+K/Ctrl+P), справка (F1), настройки (Ctrl+S), темы (Ctrl+T).
- Цветовая палитра сохранена прежней (зелёный/латунь/кость/кровь/сталь, ANSI-значения из `ui.py`); темы меняют только фон/поверхности.
- Сохранены старые механики: звуки и фоновая музыка, экран прогрева моделей с прогресс-баром, меню выбора эпохи (стрелки + Enter), канонические ответы на вопросы о личности, эффект печатной машинки (любая клавиша допечатывает ответ сразу).
- Ответы считаются в фоновом потоке (Textual workers) — интерфейс не блокируется во время запроса.
- `src/chat.py` стал диспетчером: по умолчанию запускает TUI; если терминал не интерактивный или Textual не установлен — откатывается на старый CLI.
- Старый CLI перенесён в `src/cli.py` без потери функциональности (fallback для пайпов/скриптов).
- Identity-вопросы и ответы вынесены в общий модуль `src/persona.py` (используется и TUI, и CLI).
- В `requirements.txt` добавлен `textual==8.2.8` (перенос на флешку подхватывает его автоматически через существующие setup-скрипты).
- Обновлён `README.md` (описание интерфейса, таблица горячих клавиш, структура файлов); в `.gitignore` добавлен `terminal_config.json`.
- Настройки интерфейса (тема, звук, печатная машинка, музыка, панель) сохраняются в `terminal_config.json` рядом с проектом.

### Ошибки и исправления

- **Заголовок, footer и строка ввода не отображались** — в Textual рамка (border) занимает строку внутри высоты виджета: при `height: 1` + `border-bottom` на контент не оставалось места. Исправлено: `#header` → `height: 2`, `Footer` → `height: 2`, `#input-row` → `height: 4` (контент + строка рамки).
- **Ответ бота печатался дважды/трижды** — Textual 8 доставляет `Worker.StateChanged` (SUCCESS) несколько раз для одного воркера. Исправлено: обработчик стал идемпотентным, запоминает уже обработанные события по `(id(worker), state)`.
- **История ввода по ↑/↓ не работала** — `BINDINGS`, присвоенный классу после его создания, Textual не регистрирует (фиксирует при создании класса). Исправлено: биндинги задаются в теле класса.
- **Ctrl+K не открывал палитру (только Ctrl+P)** — Textual объединяет биндинги по иерархии классов, поэтому родительский `ctrl+k` (удаление до конца строки в Input) перехватывал нажатие. Исправлено: в `QuestionInput` добавлены приоритетные (`priority=True`) биндинги `ctrl+k`/`ctrl+u`/`ctrl+d`, делегирующие приложению (палитра, прокрутка журнала).
- **Модальные окна не закрывались по Esc** — в Textual 8 у `ModalScreen` больше нет встроенного биндинга Esc. Исправлено: явные биндинги Esc (и Enter для справки) добавлены в `EraModal`, `HelpModal`, `SettingsModal`.
- **Падение при завершении прогрева моделей** — после `pop_screen()` Textual ещё пересобирает дерево главного экрана, и обращение к `#chat-scroll` падало с `NoMatches`. Исправлено: завершение прогрева вынесено в асинхронный воркер, который ждёт `pop_screen()` и появления `#chat-scroll` в DOM (`_wait_for_chat`).
- **«Ошибка обращения к DeepSeek: bad value(s) in fds_to_keep»** — Textual на время работы подменяет `sys.stderr` заглушкой с `fileno() == -1`; при первом вопросе `sentence-transformers` → `tqdm` лениво создавал `multiprocessing.RLock`, и `multiprocessing.resource_tracker` спавнил свой процесс с `fds_to_pass=[-1, ...]`, что `_posixsubprocess` отвергает. Исправлено: перед запуском TUI создаётся tqdm-лок заранее (пока stderr настоящий), плюс в RAG-воркерах stderr на время вызова подменяется на `/dev/null` (валидный fd) — защита от любых ленивых multiprocessing-спавнов внутри воркеров.
- **Командная палитра падала при открытии** — у `SimpleCommand` в Textual 8 порядок аргументов `(name, callback, help_text)`, был передан наоборот (в help попадала строка, в callback — функция). Исправлен порядок аргументов.
- **Ctrl+P не открывал палитру** — в Textual 8 биндинг палитры больше не добавляется автоматически. Исправлено: явный `Binding("ctrl+p", "command_palette")`.

### Проверки

- Headless-тесты Textual (`run_test`): полный сценарий (вопрос → меню эпохи → ответ → панель источников → темы → палитра → справка → настройки → история ввода → очистка журнала), холодный старт с прогресс-баром, печатная машинка с пропуском по клавише.
- Запуск в реальном псевдотерминале (pty): приложение поднимается, реальный вопрос к DeepSeek обрабатывается полностью (проверен ответ из 1367 символов с 12 источниками), выход по `/exit`.
- SVG-скриншоты всех экранов (главный, меню эпохи, палитра) — вёрстка проверена.
- Fallback на старый CLI проверен через пайп.
